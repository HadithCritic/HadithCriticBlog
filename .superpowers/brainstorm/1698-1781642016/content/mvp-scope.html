Design 1 of 5 — Core Vault MVP scope

The generic Obsidian-like base. No public plugin API and no Islamic-studies features yet, but built with clean seams so both slot in next. Items marked ◐ are core-but-trimmable if you want a tighter first milestone. Confirm or adjust in the terminal.

In scope (v0.1)
  • Open a folder as a vault (native dialog, remember last vault, one vault per window)
  • File explorer: tree of .md + folders; new / rename / delete / move
  • Markdown editor (CodeMirror 6): edit raw markdown, autosave + save-on-demand
  • Live Preview: inline rendering (headings, bold/italic, lists, links, code, quotes), reveal-source-on-cursor, bidi/RTL aware
  • Wikilinks [[note]]: autocomplete, click-to-navigate, create-if-missing
  • Full-text search across the vault, jump to results
  • ◐ Backlinks panel (what links here)
  • ◐ Command palette (Ctrl/Cmd-P)
  • ◐ Tag search (#tag index)
  • Settings: light/dark theme, editor prefs, vault path (stored locally)
  • External-change handling: watch vault, reload on outside edits
Deferred (later sub-projects)
  • Public plugin API + sandboxed plugin host
  • Community plugin / theme registry (obsidian-releases pattern)
  • Theme marketplace (MVP ships light/dark + CSS tokens only)
  • Islamic-studies pack: rijāl, isnād graph + validator, hadith citation ((Bukhari 5134)), Arabic morphology search, Hijrī dates, manuscript workbench
  • Graph view, canvas, multi-vault
  • Sync, mobile
  • Dual-layer PDF reader, Pandoc export

The principle

Everything in v0.1 is generic note-taking. The differentiator (Islamic-studies tooling) comes next, as the first consumers of the plugin API. The MVP's job is a fast, pleasant, RTL-correct markdown vault with clean internal seams.
