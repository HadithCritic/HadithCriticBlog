Three ways to build your workbench

Key finding: you already have a working local authoring tool at tools/blog-maker (TipTap + Express). It drafts to JSON and publishes MDX straight into src/content/articles/, with your custom components already wired. The PRD assumed a greenfield Tauri app and did not account for it. Pick in the terminal.

A — Extend blog-maker  ★ recommended

Reuses editor, draft store, MDX serializer, publish + preview pipeline, all components.
Builds new a research sidebar: corpus citation lookup + insert, rijāl lookup, isnād insert, Arabic search.

Pros

  • Fastest path to real research value
  • Reuses tested code and your publish flow
  • Rich-text fits your component-based articles
  • One stack (Node + React), no new runtime

Cons

  • Stays a local web app (run via npm run author), not a standalone binary
  • TipTap rich-text, not raw markdown editing
B — New Tauri + React + CodeMirror app (the literal PRD)

Reuses only the data (corpus / rijāl JSON).
Builds new everything: editor, file IO, Rust search engine, publish pipeline, components.

Pros

  • Native desktop binary, low RAM
  • Markdown-first with live preview
  • Closest to the PRD vision; Rust search speed

Cons

  • Large rebuild; discards the working blog-maker and publish pipeline
  • New stack (Rust / Tauri) to learn and maintain
  • Slowest to value; component-rich articles are harder in raw markdown
C — Hybrid: extend now, package as desktop later

Reuses blog-maker (as in A).
Builds new the research features now; optionally wrap the web app in a Tauri shell later for a native feel and native file access.

Pros

  • Value now, keeps the desktop-app door open
  • Defers the big stack bet until features prove out

Cons

  • The eventual desktop wrap is extra work
  • Two-phase plan

My recommendation

Go with A (or C if you want to keep the desktop option alive). Your purpose is a private workbench feeding the site, and you already have the authoring and publishing half built and tested. The highest-value missing piece is the research integration (corpus, rijāl, isnād), and that work is nearly identical in every approach. Build it into the tool you already have rather than rebuilding the tool first.
