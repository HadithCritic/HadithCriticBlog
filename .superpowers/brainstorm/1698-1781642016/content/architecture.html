Design 3 of 5 — System architecture

Tauri 2 app. A React + CodeMirror 6 frontend in the webview, a Rust core for the filesystem, watching, and search, with a typed IPC seam between them. Clean internal registries are where the future plugin host will attach. Confirm in the terminal.

Webview — frontend (TypeScript / React)
UI shell
ribbon, sidebars, tabs, status bar
CodeMirror 6 editor
markdown lang, Live Preview decorations, bidi/RTL, wikilink autocomplete, keymaps
State store (Zustand)
vault, tabs, active note, tree, settings, search, backlinks
Frontend services
Vault · Search · Settings · LinkIndex (wrap IPC)
Markdown engine
Lezer parse for editor + link/tag extraction + preview render
Registries (seams)
editor-extension · UI-slot · command · event-bus
⇅   typed IPC: invoke() commands + events   (fs capability scoped to the open vault)   ⇅
Tauri core — Rust
Vault FS commands
open/list/read/write/rename/delete/move, scoped
File watcher
notify external edits to the frontend
Search index
in-memory full-text + tags, built on load, updated on save/watch
Config store
app settings in OS config dir
⇣   plain files on disk   ⇣
Disk — you own it
Vault folder/   your .md notes + attachments  •  .silsilah/ (vault-local workspace state + settings, like Obsidian's .obsidian/)
OS app-config dir   global prefs, last-opened vault, theme choice

Decisions baked in (say if you disagree)

  • Search lives in Rust (in-memory index), so the webview never holds the whole vault. Interface-abstracted, so it can grow to Tantivy or SQLite FTS later. Alternative: keep it in JS for v0.1 simplicity.
  • Vault-local .silsilah/ folder mirrors Obsidian's model, so a vault is portable and git-friendly.
  • The dashed "Registries" block (editor-extension / UI-slot / command / event-bus) is built now as internal seams and becomes the public plugin API later, no rewrite.
