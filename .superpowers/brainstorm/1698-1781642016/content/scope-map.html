Product scope, decomposed

"Obsidian for Islamic studies researchers." A local-first markdown app you download, extend with plugins and themes, and own your data in. Below: four build layers, inner depends on outer. Answer in the terminal.

1 — Core Vault (the MVP)
Open a folder as a vault  •  file tree  •  markdown editor with live preview (bidi RTL/LTR)  •  [[wikilinks]] + backlinks  •  full-text and tag search  •  command palette  •  settings. This is the Obsidian-like base every other layer sits on.
2 — Extensibility (what makes it "yours")
Plugin API + loader (lifecycle, sandbox, the surfaces plugins can touch)  •  theme system (CSS tokens)  •  enable/configure UI. This is the heart of the Obsidian model and a real subsystem on its own.
3 — Islamic-studies pack (first-party plugins)
Rijāl lookup  •  isnād graph + chain validator  •  hadith citation ((Bukhari 5134))  •  Arabic root / morphology search  •  Hijrī dates  •  manuscript workbench. Built on layer 2, fed by your existing rijāl + corpus data.
4 — Ecosystem + distribution
Community plugin/theme registry (the obsidian-releases pattern)  •  the download / landing site  •  auto-update. Turns it from your app into a platform.

The sequencing question (answer in terminal)

Everyone agrees layer 1 is needed. The real choice is how early the plugin API and the Islamic-studies features come in. That trade-off is in the terminal.
